# ENDSTATE / 8BALL: full capability map and proposed integration order

Read-only research working note, 16 October 2026. Repository snapshot: `main` at `d7d36b842464d7ad0e974a59730a682f1739fccf`; paths below are relative to `/workspace/8ball`. This note proposes sequencing; it does not amend the sole task ledger, approve adoption or declare a study passed.

## What the project is actually trying to build

8BALL is the professional fixer/situation-management product. ENDSTATE is the reusable evidence-linked reasoning engine: understand the situation; define a human-authorised end state and boundaries; identify necessary conditions/actions and what must be learnt; compare conditional routes; forecast only where evidence supports it; rehearse explicitly hypothetical futures; select a course and approve actions separately; observe the actual result; reconsider and learn under permission. A swarm is one possible rehearsal or proposal mechanism inside this loop, not the whole product.

## Proposed sequencing and architectural integration

1. **Finish the present advertised workflow before changing its architecture.** Preserve the verified ENDSTATE kernel and current 8BALL UI. Deliberately configure a selected provider/model, rerun the unchanged four-case source-to-plan regression, exercise real cancellation/staleness/restart and the native provider journey, and obtain independent semantic and human reviews using the existing packet. Retain failures and require the unchanged B02 acceptance; don't substitute swarm consensus or catalogue output. This addresses B02-09/10/11/12/14/15/16/19/20/18, not a new optional backlog.

2. **Build secure host and durable update foundations in their existing homes.** B03 and ES02 need organisation/matter identity, evidence protection, an authorised event envelope and durable inbox/outbox ordering/replay. Model workers and future simulation runners remain unable to commit case commands or approve actions. Keep one current source of truth: original evidence plus reviewed snapshots; derive graphs/indexes rather than create a competing truth store. Implement full mandate/commitment features only through their explicit optional decisions and real dependencies.

3. **Add decision and scenario contracts before another execution framework.** Extend the current typed snapshot/course/scenario primitives with explicit premise links, scenario identity and an envelope for purpose, base revision, allowed input refs, assumptions, perturbation bounds, provider/model/prompt version, call/time/cost exposure, raw outputs and validation. Treat these as candidate contracts, not already exported APIs. Preserve conservative approval invalidation. Compare present structural question ranking with investigation-frontier alternatives under Lab A/B.

4. **Establish authored stress testing as the control condition.** Lab C starts from the existing What If/Plan Review and varies refusal, delays, authority/resource loss, stale evidence, deadline changes and competing commitments. Evaluate replay, no live mutation, disclosed family coverage, useful missed failure discovery, correction burden and operator time on representative held-out cases. This gives a meaningful baseline for adding a simulator.

5. **Put each external project behind an optional adapter, with overlapping tools treated as alternatives.** OASIS is the closest inspected social-platform rehearsal substrate; AgentSociety 2 is a broader but heavier modular simulation/replay option. Compare them separately before combining. MiroFish can be evaluated as a source-to-simulation/report orchestration reference rather than a replacement for ENDSTATE's truth/authority/planner. LangGraph Swarm/AutoGen coordinate specialist agents; they are not additional independent populations or accuracy checks. Use an orchestrator only if a measured multi-stage task outgrows the current simpler compiler. AutoGen is now in maintenance mode. OASIS's pinned Python `<3.12` requirement also argues for an isolated process/environment, not importing all research dependencies into the 8BALL runtime.

6. **Separate rehearsals from forecasts and calibrated learning.** Model-generated stress cases enter Lab D after C. Operational forecasts then compare simple baselines with model predictors on authorised historical outcomes; behavioural forecasts need their own population and labels. Run multi-actor Lab F only when it adds decision value over these simpler controls. Never turn scenario frequency or an agent's fluent statement into observed truth, authority or a real-world probability. Retain actual outputs even if a seed is available.

7. **Graduate only useful, governed pieces into the product.** Require explicit ADR/task scope, licences/dependency rights, security/authority review, fixed evaluation and rollback. B04 consumes approved playbooks/precedents and measured resolution improvements. ES04 formalises packs and proves another domain without duplicating the planner; a Sales/SDR application remains a later separately approved product, not a condition for finishing 8BALL. B10/ES10 need distinct support/commercial/compatibility and release decisions.

## What no inspected upstream supplies for us

- **A correct, professionally authorised fixer world/action model.** No generic graph extractor, population simulator or handoff library knows the lawful available actions, true actor identity/authority, indispensable causal prerequisites, exact client outcome, acceptable concession or final proof of resolution for a new case. Those need domain content, provenance and qualified review.
- **ENDSTATE's evidence and authority semantics.** Source assertions, observations, simulations, forecasts, choices, approvals and action effects must stay distinct at exact revisions. Upstream agents sending one another messages does not implement this contract or protect tenant/matter data.
- **The selected-course/premise/commitment policy.** We must define which assumptions make an adopted course conditional, which changes demand reconsideration, how obligations survive source retraction and how authorised target/fallback changes are recorded. Existing primitives help, but no importer makes the product decision.
- **A calibrated predictive dataset or causal guarantee.** We need permissioned observed outcomes, historical cutoffs, independent labels, simple baselines, calibration/drift tests and explicit abstention. A large synthetic society, debate consensus or README research claim is not that evidence.
- **Useful scenario selection and evaluation.** We must specify allowed perturbations, relevant actor/environment/action mappings, scope/cost limits, coverage/sensitivity, new useful failures and correction/operator burden. A simulator producing more text or more branches is not sufficient.
- **Independent acceptance or secure production operations.** Reviewers, supported configurations, real-provider processing permission, pilot approval, cross-tenant denial, evidence retention/recovery and commercial ownership remain project obligations. Libraries may supply components, never the completed acceptance decisions.
