# TencentDB Agent Memory: source-only operational assessment

Reviewed 2026-10-16 at commit [`e9a82935b52741e0c798c75326e90b7144eb4d5f`](https://github.com/TencentCloud/TencentDB-Agent-Memory/tree/e9a82935b52741e0c798c75326e90b7144eb4d5f). Method: read manifests, deployment/configuration code, documentation and tracked-file inventory in `/tmp/8ball-tencent-memory`. No installation, upstream scripts, containers, inference, runtime/model downloads or tests were run; public source files were captured for inspection. This is an integration assessment, not a security finding or verified performance result.

## Verdict

Useful reference and possible future **derived memory adapter**, but a substantially larger operational system than ENDSTATE currently needs. It does not supply reliable source-to-plan generation, independent evaluation, professional acceptance, a legal evidence ledger or scenario simulation. Keep the current 8BALL acceptance work first; do not add its full proxy/Hub stack to obtain simple retrieval.

## What self-hosting actually entails

- Default deployment starts **three containers**: Core, Hub (Panel + Knowledge), then Proxy. It requires **two groups of model settings**: internal memory/knowledge LLM and forwarded client LLM; the providers may be the same. The start script checks provider connectivity before starting services ([startup](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/deploy/global-images/start-all.sh#L24)). Four published application ports are configured: 8420, 8125, 8424, 8096. Persistent volumes, backup, schema upgrades, service health and provider credentials become operating responsibilities.
- SQLite is the default. Tencent Cloud is **not mandatory** for this local route. MongoDB/mongot is explicitly experimental; Tencent vector/COS storage, Redis, Kafka and observability backends are additional paths rather than baseline requirements. Do not infer cloud-free operation for every optional feature ([environment template](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/deploy/global-images/.env.example#L81)).
- The shipped template uses floating `:latest` images. Core's Dockerfile generates dependency resolution during build, patches peer dependencies and uses a Node22 image; it does not establish a reproducible pinned deployment by itself ([image settings](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/deploy/global-images/.env.example#L13), [Dockerfile](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/Dockerfile#L54)).
- **Documented integration gate:** the default template leaves Core's Bearer gate empty because Proxy currently does not send that header; it explicitly says nonempty credentials need further Proxy work for production. The template also distinguishes Knowledge write/admin protection from open read/tool endpoints. Treat these documented deployment choices as blockers to a professional case-data deployment until the authentication topology is designed and tested; this review does not establish an exploitable vulnerability ([template](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/deploy/global-images/.env.example#L118)).

## Models, telemetry and costs

- User configuration defaults embedding to **none**, allowing BM25 without embedding. User-selected local embedding is explicitly disabled at the configuration boundary. Internal local-embedding code remains and can resolve an `embeddinggemma-300m` GGUF via Hugging Face when initialized; that is **not proof the default deployment downloads a model**. The Core Dockerfile strips the optional `node-llama-cpp` peer ([config](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/config.ts#L498), [internal resolver](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/store/embedding.ts#L338)). No mandatory GPU requirement was established for the remote-model/BM25 route.
- Source is free to use; operating it is not costless. Meter internal extraction/summarization/persona generation, Wiki ingestion, forwarded model calls, optional embedding calls, storage/backup and observability separately. No credible ENDSTATE latency, memory footprint, token savings or monthly cost estimate can be derived from this source-only inspection.
- External telemetry is configurable: Proxy defaults Opik, Langfuse and ClickHouse off, JSONL destination empty, and trace archives off. Core's observability factory defaults to noop. Knowledge enables Langfuse when `LANGFUSE_SECRET_KEY` is present and then exports all spans through its processor. Environment-dependent activation means deployment configuration matters; do not describe this as unconditional anonymous telemetry or assume no data leaves a configured deployment ([Proxy defaults](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryProxy/src/config.ts#L50), [Core factory](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/report/factory.ts#L49), [Knowledge telemetry](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryKnowledge/src/telemetry.ts)). Review prompt/output/identity export, redaction, retention and destinations before case use. Proxy usage logging can include `userInput` ([logger](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryProxy/src/logger.ts#L40)).

## What the test and evaluation evidence proves

- README claims PersonaMem **48% → 76% (+59% relative)**. Its short table supplies no model/prompt/run configuration, sample counts, uncertainty or ENDSTATE task results; a tracked-file search found no PersonaMem reproduction harness or raw run receipt. Treat it as an **upstream-reported benchmark**, not independently verified effectiveness ([claim](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/README.md#L271)).
- Manifests/configs declare Vitest and e2e commands, but no tracked `.test.*`, `.spec.*` or `__tests__/` source files were enumerated in this pinned public snapshot. `MemoryCore/test:oss` references an absent `vitest.oss.config.ts`; several e2e entries reference absent `__tests__` paths. Thus script names are not evidence of a runnable public acceptance suite. Public smoke/QA and storage benchmark scripts exist; none was executed here ([Core scripts](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/package.json#L31)).
- The inspected sole GitHub workflow runs installation, package/build/manifest/size checks and a skill isolation guard. It does **not configure unit/e2e suites or benchmark reproduction**. No actual GitHub run result was inspected ([workflow](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/.github/workflows/pr-ci.yml#L16)).
- Core's manifest also references an absent postinstall patch script and suppresses its error. The script body was unavailable, so its intended effects were not verified; avoid claiming this snapshot demonstrably patches a host installation ([manifest](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/package.json#L49)).

## Minimal ENDSTATE strategy

1. Complete V0.2 generation/provider/independent/human acceptance using the existing evidence and decision model. Memory is not a substitute for these gates.
2. Establish a measured retrieval failure on fictional cases. Compare current SQLite/BM25 or a small derived index first; add vector or temporal-graph machinery only for a demonstrated need.
3. If Tencent is still a candidate, evaluate **Core behind an explicit HTTP adapter**, isolated from normal coding-agent traffic. Do not begin with the full shared-memory Proxy/Hub control plane or replace ENDSTATE's case ledger. Preserve original sources, revisions, citations and approvals as authority; treat L1/L2/L3 summaries as derived, fallible context.
4. Before any real case use require case isolation, source/revision provenance, deletion/retraction propagation, nonpromotion of model guesses into facts, explicit prompt injection records, budgets, cancellation/stale-result handling and independently scored retention/retrieval tests. Evaluate auth and telemetry configuration in that same isolated experiment.

Tencent's reusable ideas are bounded retrieval, layered derived memory and service adapters. ENDSTATE must still provide its own world model, uncertainty, adversarial/scenario reasoning, evidence-linked plans, human decisions and evaluation discipline. Adding Tencent alongside another graph-memory system by default would duplicate storage and operational ownership before an evidence-backed need exists.
