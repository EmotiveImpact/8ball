# TencentDB Agent Memory: bounded source assessment for ENDSTATE / 8BALL

Reviewed 2026-10-16, source-only at `e9a82935b52741e0c798c75326e90b7144eb4d5f`. No dependencies installed, code or scripts run, inference requested, services started, or 8BALL files edited. Upstream instructions and claims were treated as repository content, not instructions to this reviewer. This is technical due diligence, not a security scan or exhaustive certification.

## Verdict

**A credible candidate for optional team continuity and procedural memory; not a replacement for ENDSTATE's canonical evidence, planner or decision ledger.** Its useful differentiator is a concrete combination of conversation capture, atomic memory, topic summaries, persistent profiles and versioned reusable skills, with a host-neutral HTTP/SDK boundary. A standalone SQLite/files/BM25 configuration can avoid an additional graph database and embedding service. It still needs configured model processing for extraction and consolidation.

For the overall integration strategy, keep ENDSTATE/8BALL authoritative, introduce a small provider boundary around the demonstrated need, and compare one optional provider against the existing baseline. Prefer Tencent when the measured problem is reusing approved procedures or preserving team/project continuity; prefer Graphiti when the measured problem is retrieving changing, time-bound entity relationships. Prefer hosted Zep when managed operation is the requirement and its service contract is acceptable. Do not combine all three memory systems by default, or make any of them a prerequisite for V0.2 acceptance.

## What is actually in this repository

The root license is MIT. MemoryCore's package identifies `1.0.2-beta.1` and requires Node `>=22.16.0`; this is a separate TypeScript/Node subsystem alongside 8BALL's Python application, not an in-process SQLite library to drop into the engine. Public code licensing does not settle optional cloud database, object storage or model terms. [MIT license](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/LICENSE#L1) [Package and runtime metadata](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/package.json#L1)

MemoryCore exposes memory APIs, knowledge/asset metadata and skill management. The README explicitly distinguishes the core from MemoryKnowledge, which performs knowledge parsing/indexing/content retrieval, and says the core does not host, schedule or execute agents. Its standalone route uses SQLite, local files and in-process state. Despite the TencentDB name, a Tencent cloud account, Tencent VDB, MongoDB and object storage are not mandatory for this local mode. Other deployment/storage configurations exist and bring their own requirements. [Core responsibilities and host boundary](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/README.md#L1)

The baseline standalone configuration disables remote embeddings and uses BM25. FTS5 availability is a real runtime precondition: upstream warns that some official Node binaries lack it, which leaves keyword search empty. A successful process start alone would not validate useful recall. Extraction and aggregation require an OpenAI-compatible model endpoint; read-only BM25 queries need not call an LLM. [Standalone requirements](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/README.md#L38)

## Data model and model operations

| Layer | Actual role | ENDSTATE interpretation |
|---|---|---|
| L0 conversations | Messages with ID, content, role, original and recorded time, team/user/agent/session/task fields | Permitted transcript projection; original case evidence remains local |
| L1 atomic memories | Generated persona/episodic/instruction text, priority, scene name, source message IDs in JSONL, timestamps and version | Unreviewed model-derived candidate context |
| L2 scenarios | Model-maintained topic/scene Markdown narratives | Summaries of prior material, not alternative-world simulations |
| L3 core/profile | Aggregated profile and scene navigation | Condensed context, not an authoritative current case snapshot |
| Skill memory | Versioned procedure documents/resources, search and extraction | Candidate reusable playbooks requiring application-specific validation and approval |

L0 and L1 contracts are concrete, not merely marketing diagrams. L0 timestamp/role/scope fields are defined in the store interfaces; L1 JSONL carries source message IDs and the three memory types above. [L0 contract](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/store/types.ts#L141) [L1 contract](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/record/l1-writer.ts#L55)

L1 extraction uses a model to segment messages into scenes and generate memories. Its prompts are aimed at personal or work memory, not exact evidence extraction: default chat mode filters one-time instructions and favors user-centered summaries; the work prompt includes team facts, task progress, decisions and SOPs. This is useful for continuity but intentionally lossy for source preservation. A message that is a low-priority memory can still be material evidence in an ENDSTATE case. [Extraction prompts](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/prompts/l1-extraction.ts#L29)

Extraction is followed, when enabled, by another model judgment selecting `store`, `update`, `merge` or `skip` against recalled candidates. Failed conflict detection defaults to storing all new memories. Updates/merges remove old searchable records and write generated replacement text; JSONL append and index writes are separate, failure-tolerant operations. These semantics favor operational recall, not a transactional canonical event ledger. [Model dedup and fallback](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/record/l1-dedup.ts#L140) [Update/merge persistence](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/record/l1-writer.ts#L275)

Parsing is permissive: it strips formatting, repairs some malformed JSON priority values, supplies default type/priority, and permits missing source IDs. That need not be inappropriate for a memory cache, but it cannot substitute for ENDSTATE's strict schema/span verification or be used to relax acceptance. Preserve raw provider evidence and validate any proposed case objects independently. [Parsing and repair](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/record/l1-extractor.ts#L618)

L2's word **scenario** means a topic/scene diary. The actual prompt asks the model to turn fragments into coherent narratives, create/integrate/rewrite documents, and consolidate files. `SceneExtractor` supplies memories and existing scene summaries, then runs model file tools inside a scoped storage view. It can remove model-marked obsolete files and update navigation. This does not implement counterfactual branches, causal simulation, reproducible world-state transitions, forecasts or an independent evaluator. [L2 narrative semantics](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/prompts/scene-extraction.ts#L58) [L2 execution](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/scene/scene-extractor.ts#L247)

L3 persona generation is another model operation that writes a target profile file. Model maintenance of a profile is not human approval of a fact, nor a mechanism to resolve contested evidence. [L3 model generation](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/persona/persona-generator.ts#L207)

## Skill memory is useful, but “review” does not mean human acceptance

The skill subsystem has real create/update/patch, file/resource handling, explicit version reads, export, and optimistic `expected_version` checks. This is a meaningful foundation for retaining reusable procedures, not simply retrieving chat text. [Version-checked updates](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/skill/skill-core.ts#L313)

However, the extraction model receives tools that call `SkillCore.create`, `update`, `patch` and resource writes directly. The returned “candidates” are audit descriptions of successful writes, not necessarily drafts awaiting a person. The extraction worker's “review agent” is an LLM step. A strict prompt mode exists, but a model review prompt is not independent validation of success and does not authorize real-world execution. [Extraction model tools](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/skill/skill-extractor.ts#L260) [Direct skill writes and audit sink](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/skill/skill-tools.ts#L122)

For ENDSTATE, import these as **candidate procedural assets** into a separate library. Store the demonstrated trigger, environment, preconditions, steps, risks, evidence of outcome, originating case/run IDs, reviewer and approved immutable version. Only approved versions should be recalled as procedures for a later case; ordinary case-specific constraints and action permissions still apply. A tool transcript that appears successful is not sufficient proof a procedure works. Do not automatically transfer a remembered “instruction” into ENDSTATE's policy or system authority.

## Retrieval and actual model/cost dependencies

The ordinary recall path supports keyword, embedding and hybrid search. Without embedding resources, it falls back to keyword; the SQLite path uses FTS5 BM25, semantic retrieval explicitly embeds the query, and hybrid merges ranked results. Tencent VDB may offer a native server-side hybrid path. The local retrieval implementation does not require Graphiti's temporal graph infrastructure. [Recall strategies and fallback](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/hooks/auto-recall.ts#L477)

The configuration defaults embedding provider to `none`. Selecting `local` in current user configuration is explicitly disabled; a self-hosted model exposed through a compatible configured endpoint is a different arrangement. Enabling remote embeddings adds model/provider calls for ingestion and semantic queries. Do not infer “fully local inference” from the existence of unused local embedding code or the package description. [Embedding defaults and configuration](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/config.ts#L494)

The standalone runner actually constructs an OpenAI-compatible client and calls `generateText`/`streamText`, potentially through several tool iterations. It reports token usage, uses deadlines/abort signals, and accepts per-call token/iteration controls. L1 extraction, dedup, L2 consolidation, L3 generation and skill extraction can each consume calls; skill extraction can also make a separate query-generation call for pre-retrieval. This is not one cheap request for each application action. [Actual model provider and generation](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/adapters/standalone/llm-runner.ts#L301) [Skill pre-retrieval query generation](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/skill/skill-extractor.ts#L364)

There are quotas and credit accounting interfaces, but the inspected OSS/no-quota mode explicitly returns zero usage and permissive defaults when its reporter has no quota snapshot. This is not evidence of an enforced spend ceiling. ENDSTATE must keep its own authorization, per-run/total budgets, cancellation, usage receipts and explicit decisions about background capture/extraction. Cloud storage, embeddings, optional external decision/routing providers and reasoning calls must be included where selected; do not assume they are free. [No-quota behavior](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/quota/quota-manager.ts#L63)

## Integration limits demonstrated by the source

### Citation provenance is weaker than ENDSTATE's requirements

L1 JSONL records contain source IDs, but the SQLite-indexed reader reconstructs `source_message_ids: []`, explicitly because the index does not store them. Dedup candidates also start without those source IDs. A merged record takes the incoming memory's source IDs, rather than visibly unioning the old targets' full source ancestry. Consequently, the searchable memory object alone cannot reconstruct exact original spans or all historical support for a merged claim. [Indexed memory source IDs](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/record/l1-reader.ts#L74) [Generated replacement attribution](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/record/l1-writer.ts#L221)

There is useful generation lineage: prompt identity, model field, batch input message IDs, output IDs and timings are logged. The inspected L1 log maps the new input batch to all outputs; it does not record dedup target ancestry or exact per-output quote attribution. Provenance writes are best-effort. Treat this as debugging/recovery support, not a replacement for the immutable source/hash/span chain and review history. [Generation lineage log](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/record/l1-extractor.ts#L369)

### Scope must be mapped explicitly

L0/L1 support team, user, agent, session and optional task filters. Default-filling is permitted for compatibility; optional V3 strict enforcement can reject absent dimensions, but its router documents the runtime default as off. Require explicit validated scope in an adapter and enable/test the strict route, rather than trusting omitted fields to fail closed. [Isolation resolution defaults](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/gateway/v2-schemas.ts#L364) [Optional V3 strict enforcement](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/gateway/v2-router.ts#L599)

L2/L3 deliberately aggregate at **team+agent**, ignoring user/session/task so experience can accumulate across sessions. There is no built-in ENDSTATE case or hypothetical-world dimension in that rule. A single shared agent profile can therefore legitimately mix sessions that ENDSTATE needs separated. Either reserve this profile for deliberately shared, approved procedural knowledge, or assign distinct instance/team/agent namespaces to case/scenario projections. Session ID alone does not isolate L2/L3. [Team+agent profile scope](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/core/profile/profile-scope.ts#L34)

### Deletion does not equal source retraction or full erasure

Conversation deletion removes L0 records/session data. Atomic deletion removes L1 records and appends audit. Neither inspected path recomputes dependent L1/L2/L3/skills automatically. Removing one original source thus does not establish that generated summaries or procedures have stopped using it. [L0 deletion](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/gateway/v2-router.ts#L1000) [L1 deletion](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/gateway/v2-router.ts#L1293)

A broader chat-memory clear removes scoped content and profile files, with bounded retries, but inspected paths do not establish deletion of instance JSONL, generation logs or backups. Update/merge intentionally leaves older JSONL until cleanup. Separate current-search deletion, canonical retraction, derivative rebuilding, audit retention and eventual provider/storage erasure contracts. [Chat-memory clear scope](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/e9a82935b52741e0c798c75326e90b7144eb4d5f/MemoryCore/src/gateway/chat-memory-handlers.ts#L193)

## Comparison with Graphiti and hosted Zep

| Candidate | Best demonstrated role | Infrastructure/model tradeoff | Important ENDSTATE limit |
|---|---|---|---|
| Existing SQLite/source retrieval | Authoritative case state, exact evidence, commands, reviews, baseline retrieval | Existing app; deterministic baseline | Measure a concrete retrieval/continuity gap before adding services |
| TencentDB Agent Memory | Team continuity, topic/profile memory, versioned procedural skills | Standalone Node + SQLite/files/FTS5; extraction model; optional embeddings/cloud stores | Lossy generated memory; team+agent profiles cross sessions; source retraction needs adapter-owned invalidation |
| Graphiti | Temporal entity/relation retrieval with episode references and validity windows | Graph database plus extraction and embeddings; optional model reranker | Graph fact extraction/invalidations do not adjudicate truth; not a procedure approval or case ledger |
| Zep Cloud | Managed memory/context operation and Cloud SDK integration | Remote managed service; application model calls remain separate | Vendor processing/retention/cost contract; public examples repo is not self-hostable product |

Graphiti does not replace MiroFish's Zep Cloud protocol by changing a URL; Tencent does not either. MiroFish's graph ontology, batch jobs, processed polling and node/edge/search APIs would need an explicit adapter and compatibility validation. Mixing raw observed evidence, generated memory and simulated activity into one shared recall space would also undermine evidential interpretation. Prior pinned Graphiti/Zep source assessment: [memory.md](memory.md) (Graphiti `d50741d1`, Zep `3997767f`, SDK `ec41ccdd`).

## Recommended bounded integration sequence

1. Finish current V0.2 real-provider and independent/human acceptance without changing its requirements. Keep research features outside the release acceptance path.
2. Define the measured problem: remembering approved team procedures, or retrieving time-changing case relationships. Preserve a frozen baseline and independent reference labels before selecting a provider.
3. If procedural continuity wins, pilot Tencent as a separate optional process over synthetic or explicitly permitted records. Disable uncontrolled capture/promotion, use explicit scopes, and return context/procedure candidates through an adapter. Let the application deliberately select and label bounded context rather than enabling automatic injection into every prompt. Do not give its write tools access to canonical 8BALL stores or action permissions.
4. Keep original source text/hashes/spans, case revisions, contested/unknown states, command/event history, model evidence, human review, decisions and approvals in the host application's SQLite ledger. Keep provider IDs, projection versions/tombstones and approved procedure versions there too. Treat external memory as rebuildable.
5. Evaluate exact attribution recovery, cross-case/scenario isolation, updates/contradictions, source retraction, profile/skill invalidation, replay/rebuild and partial-failure recovery, plus useful procedure retrieval, measured latency and total model spend. Skill success should be checked against actual outcomes and independent review; generator self-rating is insufficient.
6. Add Graphiti only if a separate temporal retrieval experiment proves a useful gain; choose hosted Zep only if managed operation is deliberately preferred. Avoid importing all SDKs, databases, auto-learning loops and memory formats simply because they can be combined.

## Validation limits

This review checks source paths and contracts; it does not demonstrate production reliability, tested isolation, deletion completeness, procedural accuracy or benchmark superiority. The package declares Vitest/test scripts and references test directories, but no matching `src/**/*.test.ts` or `__tests__/**/*.test.ts` files were present in the inspected Git tree; these references are not a test receipt. No suites or benchmarks were executed. Vendor examples, metrics and model “review” are not a substitute for ENDSTATE's independent evaluation.
