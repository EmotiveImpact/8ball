# Ruflo memory/runtime fit: bounded source review

Pinned source: [`ruvnet/ruflo` commit `1882006a02487590c8c66a7eec8d7504f6af33c3`](https://github.com/ruvnet/ruflo/tree/1882006a02487590c8c66a7eec8d7504f6af33c3), reviewed 2026-10-16 using `git show HEAD:path` and `git ls-tree` from a no-checkout clone. Upstream instructions/skills were treated as data. No install, scripts, tests, model calls or app changes. This is a fit assessment, not a security scan or runtime verification.

## Recommendation

Ruflo belongs primarily in the **optional development tooling** lane. Its coding-agent orchestration overlaps the Codex subagents already helping build ENDSTATE. It has substantive memory/learning code worth studying, but adding the entire meta-harness would not complete 8BALL's outstanding generation/evaluation/human acceptance requirements or supply ENDSTATE's scenario model.

Do not stack Ruflo, Tencent Memory and Graphiti together by default. They overlap in persistence, retrieval, embeddings and feedback while creating separate operating and authority models. Use the existing source/evidence ledger as authority and select one narrow adapter only after a measured need.

## Concrete source versus broad claims

- **Real memory components exist:** SQLite/AgentDB bridge, vector-index integration, pure BM25+dense-score combination and MMR diversity; memory rows include explicit provenance categories (`user_claim`, `agent_output`, `system_observation`, `tool_result`, `unknown`). This is more than a collection of agent-role prompts. Provenance defaults to `unknown`, so correct caller labelling remains necessary ([memory initializer](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/src/memory/memory-initializer.ts#L25), [hybrid retrieval](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/src/memory/hybrid-retrieval.ts#L130)).
- **Defaults depend on the entry point:** shared system configuration selects a hybrid SQLite+AgentDB backend, while CLI memory routes through the AgentDB bridge where available and retains sql.js fallback. Native versus WASM, driver versions and embedding availability matter; an installed package name does not establish the active runtime ([shared defaults](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/shared/src/core/config/defaults.ts#L68), [initializer](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/src/memory/memory-initializer.ts#L225)).
- **Important embedding gate:** when real embedders fail, deterministic hash embeddings are permitted by default. `RUFLO_REQUIRE_REAL_EMBEDDINGS=1` changes this to an error. The source explicitly says hash vectors lack semantic meaning; any retrieval evaluation must require real embeddings and record the active backend/model, rather than count a successful fallback as semantic memory ([policy](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/src/memory/embedding-policy.ts#L1), [matching regression test](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/__tests__/embedding-policy.test.ts#L10)).
- **Learning is bounded, not automatic truth:** local intelligence stores patterns/trajectories and feedback; its configured instant loop is on and background loop off. Training code adapts local vector-sized MicroLoRA/scoped adapters using gradients/rewards, loading optional WASM or falling back to JavaScript. This is not evidence that Claude/Codex provider model weights are being trained, that learned advice is correct, or that outcomes improve ([intelligence defaults](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/src/memory/intelligence.ts#L141), [training initialization](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/src/services/ruvector-training.ts#L307), [training input/output](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/src/services/ruvector-training.ts#L463)).
- A concrete metric caveat: the inspected balanced learning mode reports an `improvementDelta` from mean positive input quality minus a hard-coded 0.5 baseline. That is a derived feedback statistic, **not a measured before/after task-quality gain** ([balanced mode](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/neural/src/modes/balanced.ts#L159)). ENDSTATE still needs independent held-out evaluation and a human authority boundary.

## Installation, dependencies and operating cost

- Root and CLI manifests identify **3.56.10**, with MIT licensing; root requires Node >=20. Root source license requires retaining the notice. This does not settle dependency/model/service licensing ([root manifest](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/package.json), [LICENSE](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/LICENSE), [CLI manifest](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/package.json#L44)).
- Dependency surface is substantial: multiple `@claude-flow/*` packages, optional native/WASM RuVector components, AgentDB `^3.0.0-alpha.20`, agentic-flow prerelease on the CLI path, native `better-sqlite3`, and sql.js fallback. The memory package itself depends on AgentDB. Pin and verify the actual package set/platform before an experiment ([CLI dependencies](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/package.json#L100), [memory package](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/memory/package.json#L19)).
- Root has no postinstall entry in the inspected manifest; **CLI does**. Its script searches reachable AgentDB installations and copies legacy-layout directories into those dependency trees, best effort. It also declares an exports-augmentation function, but the inspected `main()` only calls the directory-copy phase. This is install-time dependency mutation, not a passive application library import ([postinstall](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/scripts/postinstall.cjs#L137)).
- CLI setup is documented as writing `.claude/`, `.claude-flow/`, hooks/helpers, settings and `CLAUDE.md`; plugin installation is a different surface. Neither was performed. Installing in 8BALL would change its development environment and project instructions, which is unnecessary for this research ([README install comparison](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/README.md#L169)).
- Local retrieval/contrastive updates need not call an LLM, but embedding models/packages are still required. `embeddings init` defaults to downloading an ONNX MiniLM model when the optional embeddings package is available; it records a failed/skipped download if absent. Do not assume npx alone provides a working local model. Agent execution still consumes host/provider capacity; multi-agent calls and feedback/evaluation can multiply usage. No ENDSTATE cost or token-saving claim was verified ([embedding init](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/@claude-flow/cli/src/commands/embeddings.ts#L733)).

## Evidence and maturity limits

- Unlike the inspected Tencent snapshot, this repository includes many concrete memory/embedding regression tests, benchmark code and committed receipts. They are useful reproducibility material; **none was run or independently validated here**.
- Host-matrix CI explicitly runs **keyless mode**, with no model call or secret. Live mode is manual. Thus a green keyless run cannot establish live Claude/Codex model execution, recall, or task completion. Platform/host/version coverage must be read from individual matrix rows, not inferred from its name ([workflow](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/.github/workflows/e2e-host-matrix.yml#L3)).
- Only matrix rows marked `fail` cause exit1; blocked/skipped/flaky/advisory rows can coexist with exit0. ADR-490 records manual live canaries on Linux x86_64/Node22, including memory round trips and trivial provider responses, with explicit unverified platforms/events. These are bounded upstream receipts, not independent replication or ENDSTATE task evidence ([matrix orchestrator](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/scripts/e2e/host-matrix.mjs#L23), [live scope](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/v3/docs/adr/ADR-490-three-host-e2e-integration-loop.md#L117)).
- The committed multi-agent run examined has `backend: "mock"`, seed42 and synthetic pass/cost/latency values. It is not evidence of real multi-agent accuracy or spend. README also explicitly limits its console recording to mission/navigation/control actions, not completed swarm work or recall ([mock receipt](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/docs/benchmarks/multi-agent/multiagent-mock-2026-06-22T17-02-43-846Z.json#L1), [README caveat](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/README.md#L145)).
- That multi-agent benchmark's real backend explicitly prints “not yet wired” and exits2. Separate BEIR retrieval artifacts are more concrete (dataset/model/query metadata and per-query scores) and disclose baseline losses; neither demonstrates reliable scenario reasoning or source-to-plan generation ([multi-agent implementation](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/scripts/benchmark-multiagent.mjs#L184), [BEIR matrix](https://github.com/ruvnet/ruflo/blob/1882006a02487590c8c66a7eec8d7504f6af33c3/docs/benchmarks/BEIR-MATRIX.md#L19)).

## Placement alongside the other candidates

| Candidate | Relevant role | ENDSTATE boundary |
|---|---|---|
| Ruflo | Coding-agent coordination, local task-pattern memory, developer feedback/routing | Optional build tooling; overlaps existing Codex delegation. Not the professional case engine or evidence authority. |
| Tencent Memory | Shared conversation/knowledge assets, layered derived memories and provider proxy | Possible derived context service; full Hub/Proxy adds services and an injection/control plane. |
| Graphiti | Temporal entity/relationship memory | Possible domain-memory adapter when temporal graph retrieval is demonstrated necessary; does not replace original evidence and approved decisions. |

Choose using fictional cases and explicit baseline comparisons: case isolation; source/revision citations; correction and deletion propagation; actual embedding/backend identity; cancelled/stale job behavior; spend; and independent task outcomes. Keep coding-agent experience separate from client case facts. A pattern learned from an apparently successful run should enter a review queue, not silently become an approved ENDSTATE strategy or factual relationship.
