# What these four projects can bring to 8BALL and ENDSTATE

**Recommendation: evolve our native system from their strongest ideas; do not install four overlapping frameworks.** The useful improvement is a decision process that preserves disagreement, tests explicit assumptions and makes the basis of a human choice easy to inspect. More agents or a universal confidence score would not establish better decisions.

We already have deterministic planning, explicit scenarios, Plan Review, Insights, Chosen Course, scoped permissions and audited history. The opportunity is to connect and sharpen those capabilities, not rebuild them.

## The three best next slices

1. **Retained dissent and an explicit operator disposition.** Preserve original objections, linked assumptions, missing input and the human's reason for continuing or reconsidering. The in-progress brief remains bounded to four declared fictional/archetype perspectives, twelve contributions and three overlays. No synthetic “consensus” can erase disagreement.
2. **Reproducible scenario comparison.** Bind every comparison to one exact case snapshot, clock, schema and declared overlay. Test correct targeting as well as no live-state mutation. Preserve unknown, zero, false, search cutoff and external wait as different states. A saved hypothetical is not an observation.
3. **A reference-focused decision packet.** Let the operator move directly between relevant changes and export a readable account of the evidence, objections and reasons behind a choice. Apply the same current disclosure rules to UI, API, history and exports. Restricted packets must disclose omissions rather than masquerade as complete audits.

These are bounded recommendations, not three completed features or new acceptance claims. Compare the first two with the recoverable native brief before adding duplicate work. Keep specialist provider work a separate typed-contract preparation task; it is not an excuse to add a fourth framework.

## What the source review revealed

- **Isolation alone is insufficient:** a scenario can leave the original unchanged yet alter the wrong thing. Test the exact changed-field set.
- **A replay file is not proof of reproducibility:** source version, snapshot, clock, schema, inputs and output identity matter; lossy serialization must fail visibly.
- **A visible chart is not the security boundary:** upstream examples showed differences between presentation, serializer and export handling. These are source-level cautions, not proven live vulnerabilities. Our permissions must hold at the server and in every export.
- **“Calibrated” does not automatically mean experimentally calibrated:** model probabilities, routing confidence, votes and rewards measure different things. None is a reliable case-success percentage.
- **Fictional perspectives are not actual participants:** no response is not agreement; missing information is not refusal; a model's objection is not independent corroboration.

## How we should prove an improvement

Use the current native UI as the baseline, not an invented missing system. Proposed experiments include twelve fictional dissent cases, repeatable three-overlay comparisons, a twenty-event reference-navigation fixture and paired restricted views. Require zero unauthorized disclosure, factual promotion, approval changes or silent course switching. Preserve failed cases.

Separately measure whether humans find the key objection or evidence faster without missing more contradictions. Suggested lookup-time targets in the full review are hypotheses to agree before testing, not observed benefits, professional acceptance or mandatory release gates.
